# ResideWell Landing Page

This repository now includes a premium, static B2B landing page for ResideWell, built to help luxury apartment property teams request an 8-week pilot or book a short discovery call.

## 1) What this website is

- A fast, static marketing website for ResideWell.
- Focused on amenity activation, resident engagement, and low operational lift for property teams.
- Built with plain HTML, CSS, and lightweight JavaScript.

## 2) How to preview locally

Option A (Python):

1. Open a terminal in this folder.
2. Run `python3 -m http.server 8080`.
3. Visit `http://localhost:8080`.

Option B (open directly):

1. Open `index.html` in your browser.
2. Note: form mailto behavior is best tested from a served URL.

## 3) What files to edit

- `index.html`: structure, sections, CTA links, contact fields, SEO tags.
- `styles.css`: colors, spacing, typography, responsive layout.
- `script.js`: smooth anchor behavior and mailto form fallback logic.
- `website-copy.md`: all landing page copy in one place for non-technical edits.
- `launch-checklist.md`: pre-launch and first-outreach checklist.

## 4) Where to update email/contact info

- Replace `hello@residewell.com` in:
  - `index.html` (footer + mailto destination)
  - `script.js` (`contactForm.dataset.email` fallback)
- Update location text in `index.html` footer if needed.
- Add a live booking link (Calendly, etc.) by replacing CTA `href` values in `index.html`.

## 5) How to deploy

### GitHub Pages

1. Push this repo to GitHub.
2. In GitHub repo settings, enable Pages from the `main` branch (root).
3. Use the generated Pages URL as your public site.

### Netlify

1. Create a new Netlify site from this repo.
2. Build command: none.
3. Publish directory: `/`.
4. Deploy.

### Vercel

1. Import this repo in Vercel.
2. Framework preset: Other.
3. Build command: none.
4. Output directory: `/`.
5. Deploy.

## 6) Customize before sending to property managers

- Replace placeholder email and CTA destination.
- Confirm final pilot language and package pricing.
- Add founder name (optional).
- Add local proof points and case study when available.
- Confirm Metro Atlanta / North Atlanta targeting language.
- Test all links and form behavior on mobile + desktop.

## 7) What not to overbuild yet

- Do not add authentication.
- Do not add a database.
- Do not build resident or instructor portals.
- Do not add a backend unless a real workflow requires it.
- Keep this page focused on booked calls and pilot inquiries.

## Contact form note

The current form is static and uses a `mailto:` fallback generated by `script.js`.

To move to hosted form collection later, replace the form action with one of:

- Formspree
- Netlify Forms
- Tally
- HubSpot form embed

When switching providers, remove or bypass the current JavaScript submit handler.
